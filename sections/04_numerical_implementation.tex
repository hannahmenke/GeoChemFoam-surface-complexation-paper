\section{Numerical Implementation}

\subsection{Solver Lineage}

The production solver is the endpoint of a staged development path:
\begin{itemize}
\item \texttt{reactiveScalarTransportFoam}: single-phase PHREEQC transport
baseline,
\item \texttt{multiScalarTransportDBSFoam}: inert multi-species DBS transport
baseline,
\item \texttt{phreeqcDBSMixture}: aqueous and optional cell-based DBS surface
chemistry mixture,
\item \texttt{reactiveScalarTransportDBSFoam}: production DBS PHREEQC solver.
\end{itemize}

The intermediate solvers are retained in-tree as validation tools because they
provide the cleanest reduction checks for the final production solver.

\subsection{Field Locations And Discretization}

The baseline discretization keeps all chemistry-bearing state cell-centered.
This avoids introducing an extra face reconstruction for the unresolved
surface-reaction source:
\begin{itemize}
\item cell-centered: solution species, $\theta$, $\epsilon_{\mathrm{num}}$,
$a_{\mathrm{surf}}$, surface fields,
\item face-centered: $\phi$ only.
\end{itemize}

Transport uses face interpolation only inside the conservative flux assembly.
Surface chemistry remains cell-local.

For microporous image cases, the current implementation treats the cell-centered
surface-area field as an additive quantity:
\[
    a_{\mathrm{surf}} =
    a_{\mathrm{surf}}^{\mathrm{interface}} +
    a_{\mathrm{surf}}^{\mathrm{intrinsic}}.
\]
The first term is the coarse-grained phase-boundary contribution. The second is
an intrinsic volumetric surface density assigned to selected image phases
(for example the micropore phase) and scaled by the corresponding local phase
fraction inside each coarse cell.

\subsection{PHREEQC Coupling}

The PHREEQC coupling is performed through \texttt{phreeqcDBSMixture}. For each
cell, the coupling uses:
\begin{itemize}
\item the current aqueous state,
\item the physical mobile-water fraction $\theta$,
\item the current cell surface area $a_{\mathrm{surf}}$, including any
intrinsic micropore contribution,
\item the current cell surface state.
\end{itemize}

The surface mode is optional and reduces exactly to aqueous-only mode when
$a_{\mathrm{surf}} = 0$.

Cells with negligible mobile-water fraction remain chemically inactive in the
written finite-volume state. In the current implementation this is enforced at
the field level, even though the PHREEQC backend may still use an internal
dummy water volume to keep the chemistry module numerically well-posed.

\subsection{Per-Timestep Algorithm}

The production timestep is intentionally simple:
\begin{enumerate}
\item read or update the face flux $\phi$,
\item solve each aqueous transport equation in conservative DBS form,
\item push the updated cell state into PHREEQC,
\item execute the local chemistry update,
\item pull the updated aqueous and surface states back into the finite-volume
fields,
\item write diagnostics, including integrated inventory summaries.
\end{enumerate}

This is the correct baseline for a first conservative implementation because it
keeps the transport and chemistry operators individually testable.

\subsection{Why The Intermediate Solvers Remain}

The intermediate solvers are part of the scientific validation package, not
just development debris:
\begin{itemize}
\item \texttt{reactiveScalarTransportFoam} isolates PHREEQC transport without
DBS effects,
\item \texttt{multiScalarTransportDBSFoam} isolates conservative DBS transport
without chemistry,
\item \texttt{reactiveScalarTransportDBSFoam} is only trusted because it is
repeatedly reduced back to those simpler paths.
\end{itemize}

For the paper, that means the implementation section should explicitly present
the solver family as a validated hierarchy.

\subsection{Current Operating Limits}

The current validated operating limits that must be stated in the paper are:
\begin{itemize}
\item local decomposition sensitivity on tiny benchmark meshes is not
write-precision,
\item small timestep and mesh refinements shift local front shape by a few
percent on the fixed 1D benchmark,
\item the current written DBS surface fields use the inherited field-scaling
convention documented in the implementation notes.
\item for microporous image cases, the intrinsic micropore surface density is a
case input, not something inferred uniquely from the segmented image.
\item exact surface-state restart is not yet a fully validated capability for
the upgraded backend because saved \texttt{Surf\_*} fields are not pushed back
into PHREEQC exactly; the paper results reported here therefore use clean starts
for the surface-enabled production runs.
\end{itemize}

\subsection{Implementation Quantities Reported In The Paper}

To keep the manuscript aligned with the code, the following quantities should
be reported consistently in every result section:
\begin{itemize}
\item MPI rank count,
\item timestep and end time,
\item whether the case is aqueous-only or surface-enabled,
\item domain-mean aqueous concentration for the main tracked species,
\item domain-mean surface loading,
\item the field-level total-equivalent inventory when comparing across
decomposition, timestep, or mesh changes.
\end{itemize}
